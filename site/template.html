Reproduce offline

A badge on a page is not verification evidence. The same check, from the shell, with the same verification key and manifest:

node node_modules/snarkjs/build/cli.cjs groth16 verify build/<circuit>/verification_key.json public.json proof.json
python3 -c 'import json,sys; p=json.load(open("public.json")); m=json.load(open("manifest.json")); t=[x for x in m["tensors"] if x["name"]==sys.argv[1]][0]; print("commitment registered" if p[0]==t["groth16"]["groups"][int(sys.argv[2])] else "NOT the registered commitment")' <tensor> <group>

Manifests, verification keys and the circuit are in the fork luiscosio/llama.cpp, examples/receipts/zk/groth16, and in this project's registry/. Expander proofs (receipts-zk) are verified offline only: receipts-zk verify public.json proof.bin orion --commitment <registered>.

What acceptance means: the public sums s1, s2 are ggml's Q4_K x Q8_K integer core for the public activation quants and the weights behind the registered commitment. It does not establish which machine ran, when, or that any answer is correct. Groth16 proofs are zero-knowledge: the weights do not leave the prover. Setup parameters are proof-of-concept (one contributor).
